Build a full-stack SaaS web application called **N3XUS Auto Video Publisher** — a "Mission Control" platform that lets users paste a YouTube or Facebook video URL, automatically downloads the video, generates AI-powered SEO content (title, description, tags, hashtags) using Google Gemini, creates thumbnail variants, and publishes to YouTube and/or Facebook.

═══════════════════════════════════════════════════════════════
TECH STACK
═══════════════════════════════════════════════════════════════

- Monorepo: pnpm workspaces, Node.js 24, TypeScript 5.9
- Frontend: React 19 + Vite, wouter (routing), framer-motion (animations), lucide-react (icons), Tailwind CSS v4
- API: Express 5 (port 8080, proxied at /api)
- Database: PostgreSQL + Drizzle ORM
- AI: Google Gemini 2.0 Flash via REST API
- Video download: yt-dlp (Python, installed via pip)
- Video processing: FFmpeg (for 4K re-encoding, watermarking, fingerprint-breaking)
- API contract: OpenAPI spec → Orval codegen → Zod validators + React Query hooks
- Build: esbuild (CJS bundle for api-server)

DATABASE SCHEMA (PostgreSQL + Drizzle ORM)
═══════════════════════════════════════════════════════════════

Table: video_jobs
  - id (serial PK)
  - youtube_url (text) — source video URL (YouTube or Facebook)
  - original_title (text)
  - original_description (text)
  - title (text) — AI-generated
  - description (text) — AI-generated
  - tags (text) — comma-separated
  - hashtags (text) — AI-generated hashtag block
  - status (text) — enum: pending | downloading | processing | generating | ready | approved | publishing | published | failed
  - progress (integer 0–100)
  - quality (text) — enum: 360p | 480p | 720p | 1080p | 1440p | 4k | null
  - codec (text) — enum: any | av1 | vp9 | h264 | null
  - mission_type (text) — enum: normal | 4k
  - publish_mode (text) — enum: manual | auto | scheduled
  - platforms (text) — comma-separated: youtube, facebook, youtube-shorts
  - scheduled_at (timestamp)
  - thumbnail_url (text)
  - selected_thumbnail_id (integer, FK → thumbnails)
  - video_path (text) — local file path after download
  - duration (integer) — seconds
  - error_message (text)
  - created_at, updated_at (timestamps)

Table: thumbnails
  - id (serial PK)
  - job_id (FK → video_jobs)
  - variant_index (integer)
  - image_url (text)
  - label (text) — e.g. "Max Resolution", "HQ Default", "Medium Quality", "Standard"
  - is_selected (boolean)
  - created_at (timestamp)

Table: channels
  - id (serial PK)
  - platform (text) — youtube | facebook
  - channel_id (text) — platform-specific ID
  - channel_name (text)
  - thumbnail_url (text)
  - subscriber_count (integer)
  - token_id (FK → api_tokens)
  - is_active (boolean)
  - is_default (boolean)
  - created_at (timestamp)

Table: api_tokens
  - id (serial PK)
  - platform (text) — youtube | facebook
  - access_token (text)
  - refresh_token (text)
  - expires_at (timestamp)
  - is_active (boolean)
  - created_at (timestamp)

Table: publish_logs
  - id (serial PK)
  - job_id (FK → video_jobs)
  - platform (text)
  - status (text) — pending | success | failed
  - platform_url (text) — published video URL
  - error_message (text)
  - created_at (timestamp)

Table: app_config
  - id (serial PK)
  - key (text, unique)
  - value (text)
  - updated_at (timestamp)

═══════════════════════════════════════════════════════════════
VIDEO PROCESSING PIPELINE (backend lib)
═══════════════════════════════════════════════════════════════

When a job is created, startVideoProcessing() runs automatically in the background:

Stage 1 — Metadata fetch (status: downloading, progress: 5–15%)
  - Run yt-dlp --dump-json to get title, description, duration, thumbnail, tags
  - Fallback: YouTube oEmbed API for title if yt-dlp fails
  - Thumbnail fallback: https://img.youtube.com/vi/{id}/maxresdefault.jpg

Stage 2 — Download video (status: downloading, progress: 20–43%)
  Only runs if quality is set (not null/none)
  - yt-dlp format selector respects chosen quality + codec:
    bestvideo[height<=N][vcodec^=CODEC]+bestaudio/best[height<=N]
  - Tries multiple client strategies: android_vr → ios → web → tv_embedded
  - Output: .video-store/job-{id}-raw.mp4

Stage 3 — FFmpeg pipeline (status: processing, progress: 45–72%)
  Only for missionType="4k" jobs
  - Strip all metadata (-map_metadata -1) → breaks fingerprinting
  - Video filter: speed tweak (setpts=0.98*PTS), scale to target res (lanczos), crop 2px edges, drawtext watermark (center-bottom, 50% opacity)
  - Audio filter: atempo=1.02, asetrate=44982, aresample=44100
  - Re-encode: libx264 + AAC
  - FFmpeg spawned detached (detached:true + proc.unref()) so it SURVIVES server restarts
  - PID written to .video-store/job-{id}-ffmpeg.pid
  - Progress written by FFmpeg to .video-store/job-{id}-ffmpeg-progress.txt (via -progress flag)
  - Output: .video-store/job-{id}-processed.mp4

Stage 4 — AI content generation (progress: 73–90%)
  - Gemini 2.0 Flash generates: SEO title, description (500 words), 30 tags, 10 hashtags
  - Prompt includes original title, description, platform, duration
  - Saves to DB

Stage 5 — Thumbnails (progress: 90%)
  - 4 variants generated from YouTube CDN: maxresdefault, hqdefault, mqdefault, sddefault
  - Stored in thumbnails table, first one pre-selected

Stage 6 — Ready (status: ready, progress: 100%)
  - If publishMode="auto", immediately triggers publish pipeline
  - If publishMode="scheduled", waits until scheduledAt

Publish pipeline:
  - For YouTube: use stored job.videoPath (the already-downloaded file), upload via YouTube Data API v3 resumable upload
  - Includes thumbnail upload after video upload
  - For Facebook: simulated (no real FB API yet)
  - Logs every attempt to publish_logs table

Resume on server restart (resumeStuckJobs() called at startup):
  1. If FFmpeg PID file exists + process is alive → re-attach progress monitor, wait for completion
  2. If processed file exists (>100KB) → skip to content stage
  3. If raw file exists (>100KB) → skip download, re-run FFmpeg
  4. Otherwise → full restart

  - My Videos list: paginated upload history with view/like/comment counts
  - Trending Videos panel: filter by category + region

  - Each result card: thumbnail, title, channel, views, duration, tags preview

  - Title: 70 chars max, clickable, includes keywords
  - Description: 400–500 words, structured with sections, keywords naturally placed
  - Tags: exactly 30 comma-separated tags, mix of broad + specific
  - Hashtags: 10 hashtags for description footer

AI Tools endpoints generate:
  - Script: full narration script with intro/hook/body/CTA sections
  - Hooks: 10 viral title variations in different styles (curiosity, shock, number, question, etc.)
  - Translation: localize all fields to a target language
  - Comment replies: 5 reply options in different tones (friendly, professional, witty)
  - Chapters: timestamped chapter list from description content

═══════════════════════════════════════════════════════════════
YOUTUBE OAUTH FLOW
═══════════════════════════════════════════════════════════════

1. User goes to Settings, clicks "Connect YouTube Channel"
2. Server redirects to Google OAuth2 with scopes: youtube.upload, youtube.readonly, youtube.force-ssl
3. Google redirects back to /api/auth/youtube/callback with auth code
4. Server exchanges code for access_token + refresh_token
5. Calls YouTube API to get channel info (name, id, thumbnail, subscriber count)
6. Saves token to api_tokens table, channel to channels table
7. Redirects user to /channel hub page

Token refresh: googleapis OAuth2Client handles refresh automatically on token expiry

═══════════════════════════════════════════════════════════════
VIDEO UPLOAD TO YOUTUBE
═══════════════════════════════════════════════════════════════

Uses googleapis youtube.videos.insert() with resumable upload
- Reads the already-downloaded local file (job.videoPath) — does NOT re-download
- Falls back to re-download with quality-constrained format selector if file is missing
- Uploads thumbnail separately via yt.thumbnails.set() after video is live
- Sanitizes title: strips < > and control chars, truncates to 100 chars (92 for Shorts)
- Description: main text + hashtags block + tags block, max 5000 chars
- YouTube Shorts: appends " #Shorts" to title, adds Shorts to tags

SPECIAL BEHAVIORS & GOTCHAS
═══════════════════════════════════════════════════════════════

1. yt-dlp must be installed via pip (not apt): pip install --user "yt-dlp>=2026.6.9"
   Uses python3 -m yt_dlp as the command, with PYTHONPATH pointing to pip user site-packages.

2. yt-dlp client rotation for anti-throttle:
   Tries: android_vr (no cookies) → ios → web → tv_embedded in sequence.
   Format selector includes height constraint to enforce chosen quality.

3. FFmpeg detached process:
   Spawned with detached:true + proc.unref() so server restart does NOT kill encode.
   PID file written immediately after spawn for re-attach on next startup.

4. Contract-first API:
   Never write Zod validators or API hooks by hand.
   Edit openapi.yaml → run: pnpm --filter @workspace/api-spec run codegen

5. Google Fonts import MUST be the first line in index.css before @import "tailwindcss".

6. Express 5 wildcard routes: use /{*splat} not *.

7. After any route/lib file changes in api-server, always rebuild:
   pnpm --filter @workspace/api-server run build && restart workflow.

8. YouTube thumbnail upload can fail if channel is unverified — this is non-fatal,
   the video is already live. Log the error and continue.

9. Re-upload uses job.videoPath (existing file) not a fresh download.
   Only re-downloads if file is missing, using quality-constrained format selector.

10. 4K Mission jobs go through FFmpeg re-encode (fingerprint-breaking).
    Normal Mission jobs skip FFmpeg — raw download is published directly.
